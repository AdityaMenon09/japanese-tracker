## 1. What the four flashcard buttons actually do

Asked and answered in passing, but worth keeping — the ratings aren't labelled
anywhere in the UI beyond the interval hint under each one.

The buttons are SM-2 self-grading. The small number under each label is **when
that card comes back**, computed live from that card's own history; `1`–`4` are
keyboard shortcuts. The scheduler is `calc()` in `index.html`.

| Button | Means | Effect |
|---|---|---|
| **Again** | Didn't know it | Resets progress, counts a lapse, ease −0.2, interval → 0. The card is pushed back into the queue, so it returns **in the same session**. |
| **Hard** | Knew it, but a struggle | Ease −0.15; interval = 1 day if new, else previous × 1.2 |
| **Good** | Normal recall | 1 day if new → 3 days on the next success → then previous × ease |
| **Easy** | Instant | Ease +0.15; 4 days if new, else previous × ease × 1.3 |

"Ease" is a per-card multiplier starting at 2.5, floored at 1.3 — it's how fast
that card's intervals grow.

**Hard and Good both show `1d` on a new card** because both branches hard-code one
day for a first success. They aren't equivalent: Hard leaves the card at ease 2.35
and Good at 2.50, so the intervals diverge from the second review onward.

Practical version: **Good** is the default. **Again** only for a genuine blank —
it's the only rating that truly penalises a card. **Easy** when 4 days feels too
soon to see it again. Resist using **Hard** as a "sort of knew it" hedge; it drags
ease down permanently, which is the classic way to build a deck nothing ever
graduates from.

**Skip** (→) is not a rating — it moves the card to the back of the queue and
records nothing, leaving the schedule untouched.

## 2. Script filter on the words deck

The Kana deck already had a Script select. The words deck had none, so
"Words of the day" always meant the whole mixed list.

Now: **Script — Hiragana only (68) · Katakana only (59) · Both (127)**, sitting
next to Deck and Show, defaulting to Both. Counts are computed at render time, so
they stay honest as the list grows.

Implementation is small:

- `wordFilter(script)` filters `WORDS` on the `s` tag each word already carried
  (`"h"` = written entirely in hiragana, `"k"` = entirely in katakana). Returns a
  copy, so a session queue can't mutate the source list.
- `fcWordFields()` renders the select; `fcWordScript` is the element id.
- State lives in **`fcCfg.wscript`**, deliberately *not* reusing the kana deck's
  `fcCfg.script`. Sharing one key would mean switching decks quietly changed the
  other deck's setting.
- `fcCards()` calls `wordFilter(fcCfg.wscript)` instead of iterating `WORDS`
  directly, which is enough to make the due/new counts and the session queue all
  respect the filter with no further changes.

Card ids are still `"w:"+kana`, so **existing SRS schedules carried over intact** —
filtering changes which cards are offered, never their identity.

## 3. The word list: 37 → 127

Grouped in the file by script, then by sound. The point of the grouping is that
dakuten and handakuten are met **in real vocabulary** rather than as kana drills.

| | plain | dakuten | handakuten |
|---|---|---|---|
| **hiragana** (68) | やま, うみ, そら, いえ, へや, にく, やさい, くつ, おかね, おいしい… | かばん, かぎ, まど, からだ, みぎ, ひだり, かぞく, じかん, ごはん, ぎんこう, だいがく, ざっし, しんぶん, でんしゃ, じてんしゃ, でぐち, いりぐち, げんき, でんき, くだもの, たまねぎ, そば, どようび, げつようび, あぶない, だいじょうぶ, ありがとう | えんぴつ, きっぷ, さんぽ, てんぷら, しんぱい, せんぱい, かんぱい, いっぱい, ぺらぺら |
| **katakana** (59) | ラーメン, シャツ, スカート, ネクタイ, カレー, トイレ, ナイフ, フォーク, クラス, メール, シャワー, サッカー, テニス, レストラン, チョコレート, アイスクリーム, スマホ, エアコン… | コンビニ, ズボン, デパート, ジュース, ゲーム, ギター, ビル, ガラス, バッグ, ベッド, カード, ビデオ, テーブル, ダンス, エレベーター… | パソコン, スーパー, プール, ピアノ, ポケット, アパート, ピザ, パーティー, コップ, スプーン, ボールペン |

Every entry carries the alternate romaji spellings the quiz should accept:

- **n → m before p/b/m** — `shinbun`/`shimbun`, `sanpo`/`sampo`, `senpai`/`sempai`,
  `enpitsu`/`empitsu`, `konbini`/`kombini`, `tenpura`/`tempura`
- **long vowels** — `suupaa`/`supa`/`supaa`, `erebeetaa`/`erebeta`, `raamen`/`ramen`

Macrons need no variants: `norm()` already folds ā ī ū ē ō down to plain vowels
and strips hyphens, spaces and apostrophes before comparing.

The existing 22 hiragana and 15 katakana words were kept but **reordered** into the
sound groups — five of them (みず, でんわ, がっこう, ともだち, たまご) were sitting in
what is now the plain run and had to move, or the grouping comment would have been
a lie.

### A collision worth recording

**かばん and バッグ both had the meaning `"bag"`.** In *English → Japanese* with
Script set to Both, that produces two cards with an identical prompt and different
answers — unanswerable, and the SRS would punish you for guessing the wrong one.
Now `"bag / satchel"` and `"bag (handbag)"`.

Found by grouping the list on the `m` field and looking for duplicates, not by
noticing it. Worth re-running that check whenever words are added.

ビル (`biru`) and ビール (`biiru`) look like the same problem but aren't — the romaji
prompts differ, and having the pair in the deck is useful practice.

### Side effect: the quiz and Word of the day got bigger too

`WORDS` is also read by the quiz's word modes (`sample(WORDS, …)`) and by Word of
the day. Both now draw from 127 rather than 37. That was flagged at the time as a
consequence rather than a request; it stands unless it turns out to be unwanted.
The flashcard **script filter does not apply to the quiz** — the quiz keeps its own
separate `cfg.script`, which only affects its kana modes.

## 4. How it was verified without a browser

**The Browser pane never loaded.** `navigate` and `preview_start` both timed out
after 300s against the local `file://` URL, so there is **no visual confirmation of
the new dropdown** — everything below is logic-level.

Still no Node on this machine, so:

- **`cscript //E:JScript` as a syntax checker.** The whole inline script was
  extracted to a `.js` file and run. It failed with a *runtime* error
  (`document`-undefined at the IIFE call) rather than a compilation error, which
  proves the file parses. Viable because the app uses no ES6 — a check confirmed
  zero arrow functions, `const`, or `let`.
- **A JScript harness** with `filter`/`forEach` polyfills, loading the real `WORDS`,
  `wordFilter`, `sel` and `fcWordFields` straight out of the HTML by regex. It
  confirmed: 68 + 59 = 127, each filter returns only its own script, the returned
  array is a copy, zero duplicate card ids, `fcWordFields()` emits exactly one
  `selected` attribute in each of the three states, and an unrecognised value falls
  back to hiragana.
- **A PowerShell pass** over the array checked script purity character by
  character against the Unicode blocks (hiragana U+3041–309F, katakana
  U+30A0–30FF), plus duplicate words, duplicate romaji, and duplicate meanings —
  which is what caught the かばん/バッグ collision.
- **`curl` against the live site** after the push, confirming Vercel served
  `fcWordScript` and counted 68 `,s:"h"}` / 59 `,s:"k"}` entries in the deployed
  HTML.

## Environment notes (corrections to the 27 July log)

- **`git push` worked non-interactively.** Last session recorded that pushes needed
  an interactive sign-in; this one pushed to `main` from a non-interactive shell
  with no prompt. Credentials are evidently cached now.
- **`curl` is available** and is a good way to verify a Vercel deploy actually
  landed, rather than trusting the push.
- **Don't write JScript files with `Set-Content -Encoding UTF8`.** The BOM makes
  `cscript` fail with a bogus `Expected ';'` on line 1 column 31. Use
  `[IO.File]::WriteAllText($p, $s, (New-Object Text.UTF8Encoding $false))`.
  Note the consequence: without a BOM `cscript` reads the file as ANSI, so Japanese
  string literals come out as mojibake. Harmless for structural checks — UTF-8
  bytes never decode to `"` or `\` in cp1252, so the parse is unaffected — but it
  means the console output of any Japanese text is unreadable.
- Still **no Japanese voice** on this laptop, so the audio on the new cards is
  untested here. Same workaround as before: Edge, or the phone.
