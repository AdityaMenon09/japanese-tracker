## 1. The landing page

One self-contained file, in keeping with the rest of the project — no build step, no
framework, and nothing fetched at runtime except the web fonts.

Design direction came from the `ui-ux-pro-max` skill: a claymorphism-leaning playful
style for education products, a rose/indigo palette, and its motion presets. Two
deliberate departures from what it suggested:

- **The palette was pulled toward the app's own colours** rather than the skill's stock
  indigo. The page uses the tracker's washi cream (`#FBF8F1`) and vermilion seal
  (`#E0674D` / `#C64A31`), so clicking through to the app doesn't feel like a different
  site.
- **No GSAP.** The skill's motion presets assume it, but it is a CDN dependency and the
  whole point of this project is one offline file. Everything is CSS transitions plus the
  Web Animations API instead.

Typography is **Mochiy Pop One** for display and **Zen Maru Gothic** for body — both
carry kana and kanji, so the Japanese and the English are set in the same voice.

### The sky follows your clock

Five phases, chosen from the local hour, each a full set of CSS custom properties —
gradient, orb size and position, star opacity, mountain tones, cloud strength and scrim
depth:

| Phase | Hours | Look |
|---|---|---|
| dawn | 05–08 | large low sun, faint stars |
| day | 08–16 | blue sky, small high sun, no stars |
| sunset | 16–18 | large low sun in the app's vermilion |
| dusk | 18–20 | purple, sun near the ridge |
| night | 20–05 | small cratered moon, full stars |

The sun becomes a moon at night, complete with craters, and moves off-centre so it does
not sit behind the page's seal. It re-checks the hour every minute.

Two chips in the corner cycle the sky and the weather by hand, so you can see all of it
without waiting for the clock. The sky chip carries a green dot while it is tracking real
time; cycling round to the live phase hands control back to the clock.

### Weather, picked at random each visit

`clear`, `sakura`, `rain`, `snow` and `fall` — one is chosen on load. Rain and snow also
bring drifting cloud cover and a dimming layer.

**Snow puts the whole range under snow**, not just Fuji's cap: each phase carries its own
`--snow-back` / `--snow-front` pair so moonlit snow reads blue-grey while daylight snow
reads near-white, and caps appear on the side peaks too.

### The scenery

Three depth layers: hazy distant ranges, **Mt Fuji** as the centrepiece, and a darker
foreground ridge. Fuji is a wide concave cone with a jagged snow cap.

A **vermilion torii stands in front of the range**, off to one side. And a plane crosses
continuously with a contrail, plus a blinking beacon after dark.

### Interaction

Mouse parallax across six layers, scroll reveals, counting stats, and a working flashcard
that flips through the first ten hiragana — the real card behaviour in miniature.

`prefers-reduced-motion` disables the particles, the plane and the reveals, and the
particle spawner stops in a hidden tab rather than piling up.

## 2. Why the root swap needed a rename, not a redirect

The obvious fix was a `vercel.json` rewrite pointing `/` at the landing page. It would
never have fired.

> **Worth recording:** Vercel resolves routes in the order **redirects → filesystem →
> rewrites**. Because `index.html` existed, the filesystem match wins and the rewrite is
> never consulted. Renaming the files is the fix, and it needs no config at all — it
> behaves the same on any static host.

The two landing CTAs also changed from an absolute `https://…vercel.app` URL opening in a
new tab, to a relative `app.html` in the same tab. They are internal links now, so a new
tab was simply wrong.

## 4. Enter drives the quiz

Enter was bound to the answer input. Moving it to a single document-level handler fixed
two things that were quietly broken, and enabled a third.

- **Enter died once you answered.** `checkAnswer` disables the input, so the key had
  nothing listening. You had to reach for the mouse to continue.
- **Enter was swallowed by the on-screen kana keys.** With focus on a kana button —
  which is where it lands when you pick letters from the on-screen alphabet — Enter
  re-pressed that key instead of submitting.
- **Questions now advance on their own:** 1.5s after a hit, 2.9s after a miss so there is
  time to read the answer and hear it spoken. Enter or the button still skips ahead
  immediately.

The handler leaves Enter alone in every other field on the page, and calls
`preventDefault` so a focused button cannot fire its own click on top of the same
keystroke. Pending advances are cancelled when a quiz starts, when a question is left and
on the config screen, so a stray timer cannot jump you forward after you have moved on.

## Bugs found and fixed

| Where | What went wrong |
|---|---|
| Hero parallax | The mouse handler wrote `element.style.transform` directly, wiping the `translateX(-50%)` that centres the sun and torii — both drifted right on first mouse move. Now it writes `--px` / `--py` custom properties and each layer composes them onto its own base transform. |
| Torii vs mountains | First only **16px** of a 225px gate cleared the ridge, so it read as an orange blob; then correcting it left the gate floating **58px above** the ridge. Fixed by measuring the ridge height and matching the gate to it. |
| Torii vs buttons | Centred, the gate collided with the CTA row — there were only ~106px of clear sky between ridge and buttons. Moved off-centre, where the flex-centred column can never reach it at any viewport height. |
| Mt Fuji | Too narrow to read as Fuji. Base widened from 780 to 1020 units and the snow cap re-cut so its jagged edge meets the new slopes flush instead of floating inside them. |
| Floating snow cap | Fuji's cap looked detached because both mountain layers were nearly the same dark tone. The back range was lightened across every phase to restore the depth cue. |
| Weather everywhere | The particle layer was `position:fixed`, so rain fell across the cream content sections and read as scratches. Scoped to the hero, and the fall distance now comes from the hero's height. |
| Day-phase sun | At 440px it filled the top half of the screen behind the title. Orb size and position became per-phase values. |

## Verification notes

Two things made checking this harder than expected, both worth remembering:

- **Reading a computed style straight after switching phase returns the old value.** The
  sky properties carry a 1.2s transition, so `getComputedStyle` mid-transition reports
  stale colours. One check wrongly suggested the snow override had failed. Reading the
  resolved custom property instead of the animated `fill` gave the true answer.
- **Busy-waiting to sample an animation measures nothing.** A `while` loop blocking the
  main thread freezes style updates, so the plane's position read identical three times
  and looked stationary. Sampling across separate calls — or reading
  `animation.currentTime` — showed it moving correctly.
